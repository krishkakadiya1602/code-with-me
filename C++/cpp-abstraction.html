C++ Abstraction

Learn Abstract Classes, Pure Virtual Functions and Interfaces

What is Abstraction in C++?

Abstraction is one of the important concepts of Object-Oriented Programming (OOP) in C++.

Abstraction means showing only the important information to the user and hiding unnecessary implementation details.

Simple Definition:
Abstraction means hiding implementation details and showing only essential features.

Real-Life Example of Abstraction

Consider an ATM machine.

When you use an ATM, you select options such as withdrawing money or checking your balance.

You do not need to know how the ATM internally communicates with the bank server, verifies the transaction, or updates the database.

You see:

✔ Withdraw Money
✔ Deposit Money
✔ Check Balance

The internal implementation is hidden.

Another Real-Life Example

Consider driving a car.

You use the steering wheel, accelerator and brake to control the car.

You do not need to understand every internal engine operation to drive the car.

Interface: Steering wheel, brake, accelerator

Hidden Implementation: Internal engine mechanism

Why Use Abstraction?

  • It hides unnecessary implementation details.
  • It makes programs easier to understand.
  • It improves security by hiding internal details.
  • It reduces code complexity.
  • It provides a clear interface for users.
  • It makes large programs easier to maintain.

How is Abstraction Achieved in C++?

C++ commonly achieves abstraction using:

Method Description
Access Specifiers public, private and protected can control access to class members.
Abstract Classes Classes containing one or more pure virtual functions.
Pure Virtual Functions Functions declared using = 0.

Abstraction Using Classes

A class can hide internal data and implementation using private members.

Example 
#include <iostream>
```

using namespace std;

class BankAccount {

private:

```
double balance;
```

public:

```
void setBalance(double amount) {

    balance = amount;

}

void showBalance() {

    cout << "Balance: " << balance;

}
```

};

int main() {

```
BankAccount account;

account.setBalance(5000);

account.showBalance();

return 0;
```

}
```

The variable balance is private. The user interacts with it through public functions.

What is an Abstract Class?

An abstract class is a class that contains at least one pure virtual function.

An abstract class cannot be instantiated directly.

Important:

You cannot create an object directly from an abstract class.

Pure Virtual Function

A pure virtual function is declared by assigning 0 to a virtual function.

Syntax 
virtual void functionName() = 0;

A class containing a pure virtual function becomes an abstract class.

Abstract Class Example

C++ Program 
#include <iostream>
```

using namespace std;

class Animal {

public:

```
virtual void sound() = 0;
```

};

class Dog : public Animal {

public:

```
void sound() override {

    cout << "Dog barks";

}
```

};

int main() {

```
Dog dog;

dog.sound();

return 0;
```

}
```

Output

Program Output 
Dog barks

Why is Animal an Abstract Class?

The Animal class contains: 

virtual void sound() = 0;

Therefore, Animal becomes an abstract class.

The derived Dog class provides the implementation of sound().

Cannot Create an Object of Abstract Class

The following code is invalid:

Invalid Example 
Animal animal;

You cannot create an object of an abstract class because it contains an unimplemented pure virtual function.

❌ Animal animal; — Not allowed

✔ Dog dog; — Allowed

Abstraction as an Interface

C++ does not have a separate interface keyword like some other languages.

However, a class containing pure virtual functions can be used as an interface-like design.

Example 
#include <iostream>
```

using namespace std;

class Payment {

public:

```
virtual void pay() = 0;

virtual ~Payment() = default;
```

};

class CreditCard : public Payment {

public:

```
void pay() override {

    cout << "Payment using Credit Card";

}
```

};

class UPI : public Payment {

public:

```
void pay() override {

    cout << "Payment using UPI";

}
```

};

int main() {

```
CreditCard card;

UPI upi;

card.pay();

cout << endl;

upi.pay();

return 0;
```

}
```

Abstraction vs Encapsulation

Abstraction and encapsulation are related OOP concepts, but they are not the same.

Feature Abstraction Encapsulation
Main Idea Hide implementation details Bundle data and methods together
Focus What an object does How data is protected and accessed
Common Tools Abstract classes, pure virtual functions Classes, private/protected members
Example Payment interface Private bank balance

Abstraction and Virtual Functions

Pure virtual functions are declared using the virtual keyword.

Syntax 
class Base {
```

public:

```
virtual void display() = 0;
```

};
```

A derived class must provide an implementation for the pure virtual function to become concrete and instantiable.

Virtual Destructor

When a class is intended to be used polymorphically, its destructor is often made virtual.

Example 
class Animal {
```

public:

```
virtual void sound() = 0;

virtual ~Animal() = default;
```

};
```
A virtual destructor is important when deleting a derived object through a base-class pointer.

Important Points

  • Abstraction hides unnecessary implementation details.
  • It shows only essential features to the user.
  • An abstract class contains at least one pure virtual function.
  • A pure virtual function is declared using = 0.
  • Objects cannot be created directly from an abstract class.
  • Derived classes can implement pure virtual functions.
  • C++ can use abstract classes as interface-like designs.
  • Virtual destructors are useful for polymorphic base classes.

Common Mistakes

1. Creating an Abstract Class Object

Animal animal;

This is not allowed when Animal contains a pure virtual function.

2. Not Implementing a Pure Virtual Function

If a derived class does not implement all required pure virtual functions, it also remains abstract.

3. Forgetting virtual

Make the base function virtual when dynamic dispatch through a base pointer or reference is required.

4. Incorrect Function Signature

The derived function must correctly match the base virtual function.
