Python Virtual Environment

Learn how to create, activate, use and manage isolated Python environments for your projects.

What is a Virtual Environment?

A virtual environment is an isolated environment that allows you to install Python packages separately for each project.

Instead of installing every package globally on your computer, you can create a separate environment for each Python project.

Simple Definition: A Python virtual environment is an isolated folder containing a Python interpreter and packages for a particular project.

Why Use a Virtual Environment?

Virtual environments are useful when you work on multiple Python projects that require different package versions.

  • Keep project dependencies isolated.
  • Avoid package version conflicts.
  • Keep the global Python installation clean.
  • Make projects easier to share.
  • Make dependency management easier.
  • Use different package versions in different projects.
Example: Project A may require Django 4.x while Project B requires Django 5.x. Virtual environments allow both projects to use their required versions.

Python's Built-in venv Module

Python provides a built-in module called venv for creating virtual environments.

You usually do not need to install a separate package to use venv. 

python -m venv myenv

Here:

  • python runs Python.
  • -m venv runs the venv module.
  • myenv is the name of the environment.

Creating a Virtual Environment

First open your terminal or command prompt and navigate to your project folder. 

mkdir my-python-project
cd my-python-project

Now create the virtual environment: 

python -m venv venv

A folder named venv will be created inside your project. 

my-python-project/
│
├── venv/
└── main.py

Activating Virtual Environment on Windows

On Windows Command Prompt, use: 

venv\Scripts\activate

On Windows PowerShell, use: 

.\venv\Scripts\Activate.ps1
After activation, you may see (venv) at the beginning of your terminal prompt. 
(venv) C:\my-python-project>

Activating on macOS and Linux

On macOS and Linux, use: 

source venv/bin/activate

After activation, your terminal may look like: 

(venv) user@computer:~/my-python-project$

Installing Packages in a Virtual Environment

After activating the environment, you can install packages using pip. 

pip install requests

You can also install multiple packages: 

pip install requests flask
Packages installed while the virtual environment is active are normally installed for that environment rather than into the global Python environment.

Checking Installed Packages

To see the packages installed in the active environment: 

pip list

To show information about a particular package: 

pip show requests

requirements.txt

A requirements.txt file is commonly used to store the packages required by a Python project.

Create it using: 

pip freeze > requirements.txt

The file may contain entries such as: 

requests==2.32.3
flask==3.1.0

Another developer can install the same listed dependencies with: 

pip install -r requirements.txt
This makes it easier to recreate the project's Python dependencies on another computer.

Deactivating a Virtual Environment

When you finish working on your project, you can leave the virtual environment using: 

deactivate

The (venv) prefix will disappear from your terminal.

Deleting a Virtual Environment

A virtual environment is just a folder. You can delete the environment folder when you no longer need it.

Windows Command Prompt:

rmdir /s /q venv

macOS/Linux:

rm -rf venv
Be careful when using delete commands. Make sure you are deleting the correct virtual environment folder.

Virtual Environment and Git

You normally should not upload the entire venv folder to GitHub.

Instead, add the environment folder to .gitignore. 

venv/
.venv/

Then keep your dependencies in: 

requirements.txt
A common Python project structure is: 
my-python-project/
│
├── venv/
├── main.py
├── requirements.txt
└── .gitignore

Using .venv as the Environment Name

Many Python projects use .venv instead of venv. 

python -m venv .venv

On Windows: 

.venv\Scripts\activate

On macOS/Linux: 

source .venv/bin/activate

The leading dot is commonly used to make the environment directory less prominent in project listings.

Checking Python Version

You can check the Python version before creating an environment: 

python --version

On some systems, you may need: 

python3 --version

You can also check the Python executable being used: 

python -c "import sys; print(sys.executable)"

Complete Virtual Environment Workflow

A typical Python project workflow looks like this:

  1. Create a project folder.
  2. Open the terminal inside the project folder.
  3. Create a virtual environment.
  4. Activate the environment.
  5. Install required packages.
  6. Create your Python program.
  7. Save dependencies in requirements.txt.
  8. Deactivate the environment when finished.
mkdir my-project
cd my-project

python -m venv .venv

# Windows
.venv\Scripts\activate

# macOS/Linux
source .venv/bin/activate

pip install requests

pip freeze > requirements.txt

deactivate

Important Virtual Environment Commands

Command Purpose
python -m venv venv Create a virtual environment
venv\Scripts\activate Activate on Windows CMD
.\\venv\Scripts\Activate.ps1 Activate on Windows PowerShell
source venv/bin/activate Activate on macOS/Linux
pip install package Install a package
pip list Show installed packages
pip freeze Show installed packages and versions
pip freeze > requirements.txt Save dependencies
pip install -r requirements.txt Install dependencies from a file
deactivate Deactivate the environment

Best Practices

  • Create a separate virtual environment for each project.
  • Use .venv or venv as the environment folder.
  • Add the environment folder to .gitignore.
  • Keep project dependencies in requirements.txt.
  • Activate the correct environment before installing packages.
  • Use compatible package versions for your project.
  • Do not upload the complete virtual environment to GitHub.

Important Points

  • Virtual environments isolate project dependencies.
  • Python provides the built-in venv module.
  • Use python -m venv .venv to create one.
  • Activate the environment before installing project packages.
  • Use pip to install packages.
  • Use requirements.txt to record dependencies.
  • Use deactivate when finished.
  • Do not commit the venv or .venv folder to Git.
